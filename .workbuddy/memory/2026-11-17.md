## 多 provider 独立会话 + 退出语义重构

用户讨论确认：退出应只退出**当前 provider**，不影响其他 provider 的登录态（batata 登录→切 consul→在 consul 退出→batata 仍登录，apollo 同理）；匿名 Consul 也要能正常退出；切到已登录的 provider 应直接进入、不重复输凭据。Q1=A（退出落 /login 并默认选中刚退的 provider），Q2=A（匿名退出=离开 consul，去 /login 可重选）。

### 根因

- `authStore.currentUser` 是全局单例，`restoreSession()` 有 `if (currentUser) return` 短路 → 切 provider 不重建身份。
- `logout()` 一次性清掉三家所有 key。
- router guard 在 `consul ACL disabled` 时把 `/login` 强制弹回 dashboard → 匿名退出无效。

### 改动

- `src/stores/auth.ts`：`currentUser` 改为「当前 provider 凭证的视图」，`getSessionForProvider(p)` 按各自 key 解析；`restoreSession(p?)` 去掉短路，可显式切 provider 重建；新增按 provider 的 `signedOutProviders` 集合（持久化 `batata_signed_out_providers`，逗号分隔）+ `isProviderSignedOut()`；`consulAnonymousAllowed` 同时受 ACL loaded/disabled 与「未显式退出 consul」约束；`loginAnonymously()` 复现原「跳过登录」行为；三种 login 各只清自己的 signed-out 标记；`logout()` 只清当前 provider 的 key 并标记该 provider 已退出。Consul/Apollo 的可读 token 名存 `consul_user`/`apollo_user`（不再把 token 尾 8 位当用户名）。
- `src/composables/useProviderSession.ts`（新）：统一 `switchToProvider(p)`（setProvider + switchProviderRoutes + restoreSession(p)）+ `enterProvider` + `homeForProvider`。
- `src/router/index.ts`：匿名 consul 分支改用 `consulAnonymousAllowed` 并先 `restoreSession('consul')`；退出后不再弹回。
- `src/layout/BatataLayout.vue`：`handleSwitchProvider`/disabled fallback 走统一入口；右上角身份统一显示 `user.name`（移除 `consulTokenDisplay` 的 token 尾显示）。
- `src/views/LoginView.vue`：`switchTo` 走统一入口，已登录 provider 直接进入；新增「已退出 Consul」匿名重进面板；`continueWithoutLogin` 用 `loginAnonymously()`。
- `src/i18n/translations.ts`：新增 `consulSignedOut` / `consulSignedOutHint`（EN+ZH）。

## 确认：Consul KV 文件夹行可以无限点击（已修）

- 用户截图来自 ERP 测试基座（28081），红框是进入 `erp/api-service,development-local/` 后仍出现的 `erp/` 文件夹行；每点一次都把 `erp/` 追加到 prefix，行又重新出现。
- 根因是**前端 API 契约与 Consul 上游不一致**：`src/api/consul.ts:102-105` 的 `listKVKeys(prefix)` 请求 `GET /v1/kv/?keys&prefix=<p>`，但 batata 后端 `crates/batata-plugin-consul/src/kv.rs:1778-1779,1843-1847` 从**路径** `match_info["key"]` 取前缀，`KVQueryParams` 根本没有 `prefix` 字段，所以 `?prefix=` 被忽略 → 永远返回全量 key。`src/views/consul/KVListView.vue:283-353` 再把不属于当前 prefix 的兄弟 key 折叠成 `erp/`，点它就无限循环。
- 现场实测：`GET /consul-api/v1/kv/?keys&prefix=erp/api-service,development-local/`（以及直连 28500 同样请求）返回 5 个全量 key；`GET /v1/kv/erp/api-service,development-local/?keys` 只返回目标 key；`?keys&prefix=erp%2F&separator=%2F` 返回 `["erp/"]`，正好解释截图里的行。
- 上游 Consul 前端 `ui/packages/consul-ui/app/adapters/kv.js:12,14-30` 用 `GET /v1/kv/<prefix>?keys&separator=/`，`app/services/repository/kv.js:83-108` 还会过滤掉文件夹自身。
- 建议修法（待用户确认）：`listKVKeys` 改为路径前缀 + `separator=/`，并让 `displayItems` 适配“后端已折叠”的返回（跳过 folder 自身、不再本地折叠全量 key）；补 e2e：兄弟 key 场景下进入某目录后不应再出现父目录行。本轮只读确认，未改代码。

### 修复落地（用户："修正"）

- `src/api/consul.ts` `listKVKeys`: `GET /kv/<prefix>` 路径前缀 + `keys` + 可选 `separator`（不再用 `?prefix=`）。
- `src/views/consul/KVListView.vue`: `fetchKeys` 传 `separator='/'`；`displayItems` 重写为适配后端已折叠返回（folder 以 `/` 结尾 / 叶子为完整 key），加 `key.startsWith(prefix)` 防御过滤，跳过 folder 自身，保留精确 leaf 搜索显示；删除原本地全量折叠逻辑（无限点击根因）。
- `e2e/helpers/consul-api.ts` `listKV`: 同样改路径前缀 + `separator=/`。
