# Batata SVG Logo Replacement Assessment

> Scope: evaluate whether the design tool at `~/work/aistudio/batata-logo-studio`
> can replace the branding assets of `batata-ui` (and, by extension, the
> `batata/console-ui` build served by the backend). Source-verified on
> 2026-11-20. The assessment itself replaced no asset; section 8 records the
> replacement that was subsequently made from an exported SVG.

## 1. Verdict

**Yes, it can replace the current assets — but not by copying a file.** The
studio is an interactive **generator**, not a brand asset package: the
repository contains zero exported `.svg` / `.png` / `.ico` files. A design
decision (concept, palette, lockup) must be fixed first, then a production
asset kit must be exported and hardened before it can land in `public/`.

Replacing only `public/logo.svg` would also be incomplete: `favicon.ico`, the
two PNGs, an unused Vue scaffold logo, and the backend's `console-ui` copy all
need to move together, otherwise light/dark surfaces, tab icons and the
deployed console will show different marks.

## 4. Technical compatibility

**Compatible**

- `icon-only` output is `viewBox="0 0 100 100" width="512" height="512"` —
  pure vector paths plus an inline gradient, no `<text>` and no external
  dependencies. It is a valid drop-in for the 512-based `public/logo.svg`.
- Geometry is parameterised (stroke width, corner radius, scale, rotation,
  container shape), so a 16px-optimised variant can be generated from the same
  source of truth.
- `swiss-leaf` is explicitly designed for 16x16 favicons and collapsed sidebar
  icons; `showNodes: false` keeps it legible at small sizes.
- `ExportView` already produces Vue 3 component code, CSS tokens and a GitHub
  social card, which covers downstream documentation needs.
- `BrandSpecs` computes live WCAG contrast ratios and defines clearspace /
  minimum sizes (16x16 favicon, 120px minimum horizontal lockup).

**Must be fixed before production**

1. **Lockups must not be used as favicons.** `horizontal` / `stacked` output
   uses `<text font-family="'Bricolage Grotesque', system-ui, sans-serif">`.
   Google Fonts are loaded by the studio's `index.html` but are **not** part of
   the SVG. In a browser tab, an `<img>`, or a PNG rasterizer the wordmark
   silently falls back to `system-ui`, so the asset is not reproducible. Fix:
   convert the wordmark to outlines (`<path>`), or use `icon-only` for all
   raster/favicon assets and keep text lockups only for in-app HTML.
2. **`rgba()` in SVG presentation attributes.** e.g.
   `stroke="rgba(255,255,255,0.12)"` (dark container) and
   `fill="rgba(255,255,255,0.86)"` (accent). SVG 1.1 renderers and some
   favicon/ICO pipelines do not parse `rgba()`. Fix: use `stroke="#FFFFFF"`
   plus `stroke-opacity="0.12"` / `fill-opacity`.
3. **Small-size contrast.** The default gradient plus `subtle` badge tint
   (`#FFF7ED`) loses definition at 16px. Measured against white:
   `#EA580C` = **3.56:1** (passes the 3:1 non-text/graphical AA threshold),
   `#F59E0B` = **2.15:1** (fails); against `#0F172A` `#EA580C` = 5.02:1.
   Fix: use `solid` fill with `#EA580C`, `containerShape: 'none'`, and avoid
   the amber endpoint as a foreground at small sizes. Provide a separate
   dark-surface variant.
4. **ICO / PNG generation is a separate step.** The studio's
   `downloadPngFromSvg()` produces square PNGs but no `.ico`; `favicon.ico`
   must be generated from the final SVG with an external converter, and
   `logo-192.png` / `logo-256.png` regenerated to match.
5. **Two-repository sync.** `batata/console-ui` is an untracked build artifact.
   Changing `public/` alone does not change what the backend serves until
   `pnpm build:ui` runs and copies `dist` over it.

**Licensing / provenance**

Generated in Google AI Studio (`ai.studio/apps/27b08368-...`). No third-party
image or icon asset is embedded. The five webfonts referenced by the studio
(Bricolage Grotesque, DM Sans, JetBrains Mono, Outfit, Plus Jakarta Sans) are
Google Fonts under the OFL, but they are referenced at runtime rather than
bundled; outlining the wordmark removes any font-redistribution question.
Confirm the intended brand ownership before publishing the asset kit.

## 5. Recommended replacement plan

1. **Freeze the design**: pick one concept (recommend `swiss-leaf` for the
   favicon; optionally `tuber-mesh` for the README/social lockup), one palette,
   and the wordmark text. Record the chosen `LogoConfig` in this repo.
2. **Export from the studio**: icon-only SVG (light + dark variants),
   horizontal lockup SVG, PNG sizes (16/32/192/256/512), and the GitHub social
   card.
3. **Harden**: outline the wordmark, replace `rgba()` with opacity attributes,
   verify the 16px favicon by rasterizing it, and check contrast on both light
   and dark surfaces.
4. **Replace in `batata-ui`**: `public/logo.svg`, `public/favicon.ico`,
   `public/logo-192.png`, `public/logo-256.png`; delete the unused
   `src/assets/logo.svg`; keep `index.html` icon declarations unchanged.
5. **Optional UI adoption**: add a Vue brand component (the studio generates
   one) to `BatataLayout.vue` if the mark should appear in the header/sidebar.
6. **Sync the backend** with `pnpm build:ui` so `batata/console-ui` receives
   the same assets.
7. **Verify**: `pnpm type-check`, `pnpm vitest run`, Playwright suite, plus a
   visual check of the tab icon at 16px in light/dark browser themes.

## 7. Open decisions

Resolution as of 2026-11-20: the canonical mark is `tuber-mesh` with the
`batata-terracotta` palette, deployed **without any wordmark**; the mark stays
favicon-only for now (no change to `BatataLayout.vue`), and no intermediate SVG
is kept in the repository root. See section 8. The remaining items below are
still open.

- Which concept and palette become canonical (single mark, or `swiss-leaf` for
  favicon + `tuber-mesh` for marketing)?
- Should the mark appear inside the console UI, or stay favicon-only?
- Should `logo-192.png` / `logo-256.png` be kept (they are currently unreferenced)
  or dropped in favour of the SVG + ICO pair?
- Who owns the final brand asset kit and where it is versioned — this repo,
  `batata`, or the studio repo?

## 8. Decision and implementation (2026-11-20)

The exported horizontal lockup `batata-tuber-mesh-horizontal.svg` was placed in
the repository root, with the requirement to keep the logo mark only and drop the
wordmark. A mark-only derivative was produced from it:

| Item            | Value                                                                                                                                                                                                                             |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Source          | `batata-tuber-mesh-horizontal.svg` — `viewBox="0 0 363 108"`, two `<text>` nodes starting at `x=126`                                                                                                                              |
| Chosen config   | concept `tuber-mesh`, palette `batata-terracotta` (`#EA580C` / `#F59E0B`), `subtle` squircle container on `#FFF7ED`, `iconScale` 0.720                                                                                            |
| Canonical asset | `public/logo.svg` — the only SVG versioned in this repository                                                                                                                                                                     |
| Transform       | removed both `<text>` elements, removed the lockup's `translate(4 4)` wrapper, dropped the unused `batata-cgrad` gradient, and normalized to the studio's canonical `icon-only` `viewBox="0 0 100 100"` with `width/height="512"` |

Hardening verified on the result: valid XML, no `<text>`, no `font-family`, no
`rgba()`, no external `href`, and only the referenced `batata-grad` gradient
remains. Neither the exported horizontal lockup nor the intermediate mark-only
SVG is kept in the repository root — the studio remains the source of truth for
re-exporting a lockup, and `public/logo.svg` is the single canonical asset.

All raster/favicon assets were regenerated from the same mark so the kit stays
consistent:

| Asset                 | Before                     | After                                       |
| --------------------- | -------------------------- | ------------------------------------------- |
| `public/logo.svg`     | Shield mark, `0 0 512 512` | Mark-only, `0 0 100 100`                    |
| `public/favicon.ico`  | 15 KB shield ICO           | 3.2 KB PNG-backed ICO with 16/32/48 entries |
| `public/logo-192.png` | Old shield raster          | 192x192 RGBA render                         |
| `public/logo-256.png` | Old shield raster          | 256x256 RGBA render                         |

`index.html` was intentionally unchanged: its two icon declarations still
resolve to `/logo.svg` and `/favicon.ico`. Rasterization used headless Chrome
with a transparent background, and the ICO was assembled with a small stdlib
script — no new project dependency was introduced. The 16px render was visually
checked; the tuber/mesh mark remains legible at favicon size.
